## Chat guidance (Discord, 2026-10-31 to 11-02)

- **celarye** (inkdex lead): guidelines exist "so it's easier for devs to steer the agents in
  certain design patterns and prevent it from making stuff more complex and harder to read than it
  needs to be"; "people make classes full of static methods calling functions not in classes for
  no reason and so much code to do so little".
- **Seyden** (Mana developer): full URLs as ids are saved on every chapter (source id, content id
  and chapter id for 2,000 to 3,000 chapters) and bloat the reader's database; so do redundant
  data per property and full-string tags. Fine only when the site itself uses URL ids.
- **duck**: using keiyoushi sources should be the last option for iOS.
- **niclimcy** sent the guide condensed in `AGENTS.md` §3 (function-based design, utils scope,
  aggressive inlining, one generic list parser, session caching, Cheerio typing, comments).

## Verified in code or on a device

- The published `paperback-cli test` exits 0 when tests fail and skips a source with no test file
  (`dist/src/commands/test/index.mjs`); `scripts/check-tests.mjs` covers it.
- Tests need Node 24 (`engines`): under Node 22 a source fails to load with
  `Float16Array is not defined` and the run reports 0 failures.
- The test VM gives Node's full WebCrypto; the app's bridge has no AES-CTR. Toonkotsu decrypts in
  TypeScript; `test/unit/Toonkotsu.test.ts` checks it against Node's AES-CTR (a wrong counter fails
  18 of 19 cases).
- The mock request manager passes the original request to every request interceptor.
- Device findings from kodama's repository: `Metadata` undefined crash, `0` becomes `false`, id
  charset on every id field, rating as a percentage, "Vol. TBA", "Chapter N - title", XHTML rules.
- Merged code disagrees with three written rules, so the checker only notes them: `SelectRow`
  `options` (11 sources, MangaFire in October 2026), emoji (HiveToons, MangaFire), and `function`
  declarations in parsers (Mangago, AllManga).
